把本会话已完成的分析/计算/验证沉淀为一份可交付的工程报告：$ARGUMENTS

结构（严格遵守，纯文本 Markdown）：
1. **报告摘要** — 三句话以内：问题、方法、核心结论
2. **背景与目标** — 需求来源、评估对象、约束条件
3. **分析与证据** — 本会话的关键计算/仿真结果，逐条注明来源工具与参数（含单位）；有 PNG 产物给出 plots/ 路径
4. **结论** — 与证据一一对应，不引入未验证的新断言
5. **实施建议** — 按优先级排列（P1/P2/…），每条给预期收益与代价
6. **风险与限制** — 近似模型口径（如雨衰 ±20~30%）、未验证前提、数据局限
7. **后续行动** — 需要用户补充的信息或下一步验证

落盘规则：
- 若当前会话有 write 工具（优化模式）：写入 `reports/<YYYY-MM-DD>-<主题短横线>.md`（会触发审批，属预期），然后告知路径。
- 若无 write 工具（问答模式）：直接在回复中输出报告全文，说明可复制保存。
- 报告只汇总本会话已有结论；发现证据缺口时列入「后续行动」，不要现场编造数据。
