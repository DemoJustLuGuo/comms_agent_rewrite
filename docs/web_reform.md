# Web 工作台改革

执行范围核验：2026-11-18。主产品入口为 pi-web，沿用 pi 会话引擎。

## 交付任务

1. Web 工作台：结论优先、证据折叠、实时状态、审批待办队列；验证后独立提交。
2. 工具发现与组合：统一 Web 活动工具策略、按需发现、结构化计算链、读写执行审批；验证后独立提交。
3. 实验闭环：隔离候选工作区、基线与指标、持久化实验记录、验证与候选应用；验证后独立提交。

## 验收场景

- 普通问答先展示答案，过程可展开；运行时失败与待办不被折叠。
- 并行审批、刷新、取消、拒绝均以服务端当前请求为准。
- 通信定量任务调用确定性工具；工具失败明确报告；按需工具清单核对实际 provider 请求。
- 组合调用校验参数、权限与每步实际输出，传值依靠结构化字段及其单位。
- 实验验证明确记录目标工作区、基线版本、输入与随机种子；失败候选不能应用。
- ModulationPy 完成真实实验，恢复后可审阅，原始工作区与既有修改受到保护。

## 设计边界

- 重点改造 Web，复用现有会话分叉和历史树。
- 结果使用数值、单位、表格和既有图片预览，不增加专用图表渲染框架。
- 审批采用读、写、执行分类；候选应用、本地提交和推送分别授权。
- 默认入口提供统一通信工作流，旧脚本作为兼容入口保留。
- 实验状态与事件记录是结果判定的来源，模型的建议不替代验证状态。
- 分阶段提交只包含当前任务变更，保留开始时已有的暂存区和工作区改动。

## 任务二验收记录

核验日期：2026-11-18，范围为工具发现、组合和审批分级。

- Web 默认使用按需策略，保留全量和关闭选项；关闭后保留注册表以便重新开启。
- `comms_find` 按任务匹配并启用工具，每个新任务重新收敛到常驻集合；工具策略随会话持久化。
- 链路预算、干扰分析和 AWGN 容量提供全精度结构化结果与单位；原有文本输出保持一致。
- `comms_batch` 仅允许上述三种固定计算工具，最多八步；引用检查前序结果和单位，逐步校验参数与权限。
- `scripts/check-web-reform.sh` 验证实际 pi → OpenAI-compatible 请求，使用本地 SSE 测试 provider：默认 10 个工具、发现后 13 个、全量 34 个；schema JSON 长度分别为 6608 与 29032 字符。这是结构长度证据，不是实际 token、缓存或模型路由准确率测量。
- 类型检查、审批门 8 项、Python 域工具回归 136 项通过；临时 provider 验证下一次请求获得新工具，下一任务再次精简。
- 原有 `scripts/check-runtime.sh` 的域工具白名单守卫保留。新增运行时守卫验证按需与全量请求以及白名单之外不可发现的行为，不把默认活动集合当权限上限。
- 实际 Web API 验证：默认活动列表为 10 个工具，关闭后为 0 个，重新开启恢复 10 个；原有运行时自检通过。
